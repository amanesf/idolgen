# 実装計画（Procedural-DOL GENERATIONS）

> `docs/GDD_final.md` を実装可能な単位に分解したロードマップ。
> フェーズは「MVPループを早期に一周させ、その後で各層を深掘りする」方針で並べている。
> 各フェーズは完了後に次へ進む前提だが、バトル(陣形パズル)の作り込みだけは
> 複数フェーズにまたがる継続タスクとして扱う（Phase 1 で最小構成、Phase 4 で本格拡張）。

## 用語の訂正

GDD §3.4 の「個別強制引退（オーバーワーク）」は、**キャラクターの死亡ではない**。
スタミナ枯渇したメンバーはその場でロースター配列から除籍される「強制引退」であり、
実装・UI文言・変数名のいずれにも「死亡（death）」という表現・概念を用いない。
既存コードに `death` 等の命名が残っている場合はPhase 1着手時に `forcedRetirement` 等へ
是正する。

## Phase 1: MVPループの結線（最優先）【完了】

目的：スカウト→仕事選択→陣形パズル→結果反映→強制引退/撤退 の一周を、
薄い実装でよいので実際にプレイして通す。経営レイヤーの深さより「ループが閉じること」を優先。

- `js/scoutView.js` を新設し、ホーム画面から予算選択→候補生成→契約金を払って
  雇う導線を追加（`hireIdol()`）
- 仕事選択画面（`renderStageSelect`）・バトル結果のロースター/資金反映
  （`applyBattleResult`）は元々実装済みだったため変更なしで確認のみ
- `saveGameState`/`loadGameState`（`localStorage`）を追加し、日送り・バトル結果・
  スカウト成立・リスタートのタイミングで自動保存するようにした
- コード中に「死亡」を連想させる表記（`パーマデス`）がないか確認し是正済み（前回コミット）

### タスク
1. **ロースター状態の統合**（`js/state.js`）
   - `scoutGenerator.generateCandidate()` の出力をロースターに追加できる形に整形
   - 固定の `IDOLS` 配列（`masterData.js`）を初期ロースターとしてのみ残すか、廃止するか決定
   - 強制引退（`forcedRetirement`）でロースター配列から即除去する処理
2. **仕事選択画面（簡易版）**
   - 既存 `STAGES`（`masterData.js`）から1件選ぶだけのシンプルなUI
   - クライアント格付け・バーター営業等の経営判断はまだ入れない（Phase 3で追加）
3. **バトル結果のフィードバック**
   - `success` → 契約金を資金に加算、経験値相当の何か（Phase 2まで簡易でよい）
   - `fail`（強制引退）→ ロースターから除去、UI上に通知
   - `retreat` / `timeup` → GDD §3.11 のペナルティ（違約金・信頼度低下）は簡易値でよい
4. **セーブ／ロード（最低限）**
   - `localStorage` への自動保存・復元
   - JSONエクスポート／インポートはPhase 1では後回し可（§13、必須ではない）
5. **用語是正**
   - コード中の `death` 関連命名があれば `forcedRetirement` に統一

### 完了条件
- スカウトでキャラを増やし、仕事を選び、陣形パズルをプレイし、結果が資金・ロースターに
  反映され、リロードしても状態が残る、という一周が実際に動く。

## Phase 3: 仕事選択の経営レイヤー（§6）【完了】

- 事務所ランク（`masterData.js`の`AGENCY_RANKS`、累計ファン数の閾値）を新設し、
  ランクに応じて営業モードが自動遷移するようにした（`js/jobBoard.js`の
  `getAgencyRank`/`getAvailableStages`）。低ランクは「ドブ板営業（能動）」＝
  解放済みの仕事を全件リストして自分で選ぶ、高ランクは「オファー選別（受動）」＝
  日替わりで数件だけ提示される、という切替を実装
- クライアント格付け（クリーン／グレー、`BALANCE.clientTiers`）を追加。
  期待値ライン・報酬・スタミナ経済の3つに係数として乗る。グレー案件は
  成功時にも一定確率で悪評（ファン離反）が発生する簡易スキャンダル判定つき
- バーター営業（`BALANCE.barter`）：ステージの推奨レベル（`recommendedStatLevel`）を
  実際の編成の平均実力が大きく下回ると自動判定され、期待値ラインが上がる代わりに
  成功時のファン増加が上乗せされる
- トレンド倍率（`BALANCE.trend`）：ステージごとに設定した`trendAttribute`と
  出演メンバーの属性が一致するとスコア効率が上がり、外れると下がる
- 上記はすべて既存の期待値ライン・スタミナ経済パラメータ（`js/battle.js`の
  `createBattleState`/`resolveTurn`）に係数として乗るだけの実装にとどめ、
  陣形パズル本体（フォーメーション・被弾ロジック等）は変更していない
- ステージ側マスターデータに`clientTier`/`trendAttribute`/`recommendedStatLevel`/
  `minRankId`を追加し、ランク解放限定のグレー案件を2件追加（`stage_004`/`stage_005`）

## Phase 4: バトルの本格拡張（§3.8 会場特性、継続タスク）【一次実装完了】

- 会場ダメージパターン(`masterData.js`の`DAMAGE_PATTERNS`)を9種実装し、
  `js/battle.js`の予兆(`primeTelegraph`)・被弾解決(`resolveDamageTargets`)を
  パターン駆動に書き換えた: 単体ランダム／前列一斉／狙い撃ち(弱肉強食型)／
  センター集中／クロスファイア(隣接連鎖、`FORMATIONS.*.adjacency`を新設)／
  無差別乱舞／属性狙い撃ち(トレンド相性型)／回復封じ／ジリ貧全体(消耗戦型)。
  「目標の逆行」(ステージHP回復型)も期待値ライン自体を毎ターン伸ばす形で実装
  （`battleState.targetScore`をターン経過で増加）
- 残り3属性を追加し、GDDの10属性がすべてbattle.js側に実装された:
  🌊波(ターンを重ねるほどスコア倍率が伸びる逓増枠)、🎭影(隣接枠の被弾を
  肩代わり、上記のクロスファイア用に追加したadjacencyを流用)、
  🌟星(センター固定なら大幅強化・センター外なら大幅減衰)
- `js/battleView.js`のスコアゲージが`stage.targetScore`ではなく
  `battleState.targetScore`(クライアント格付け・バーター・目標の逆行を
  反映した実効値)を参照するよう修正(既存のPhase 3実装で見逃していた表示バグ)
- 未実装のまま残した会場特性(残タスク): 「サビ限定集中砲火」「カウントダウン
  爆発」はターンの種類(サビ等のフェーズ)の概念が、「人気投票型」「メンタル
  連動型」はファン人気・ストレス等の未実装ステータスが前提となるため、
  それぞれの土台となるシステムを作る回でまとめて追加する
- 熱量ゲージ・コンボ・予兆システム自体の深掘り(新しいゲージ演出等)は
  今回未着手のまま

## Phase 7: 社員・組織／財務・リスク（§7, §8）【完了】

- 社員システム(`masterData.js`の`STAFF`、`js/office.js`)を実装。4職種7種:
  スカウトマン(眼力=掘り出し物率↑/交渉力=契約金↓/人脈=予算上限↑)、
  マネージャー(メンタルケア=悪評確率↓)、プロモーター(SNS運用力=ファン増加↑/
  火消しスキル=悪評ペナルティ↓)、エージェント(コネクション=オファー選別の
  ランクを1つ先取りできる、`jobBoard.js`に反映)。雇用/解雇と一覧は
  新設の「事務所運営」画面(`renderOffice`)から行う
- 月次決算の簡易版(`settleDailyFinances`)を`advanceDay`から呼び出し、
  社員・トレーナーの日次人件費を自動で引き落とすようにした(既存の
  `TRAINERS.hireCostPerDay`が今まで参照されていなかった欠落も解消)
- 資金調達(§8): 銀行融資(即時現金・完済まで日次自動返済)とタニマチ出資
  (即時現金・返済不要だが日次で悪評リスク)を`office.js`に実装
- 記者会見(社長の3択+トカゲの尻尾切り、`renderPressConference`): グレー案件の
  悪評発生時、即座にファンを減らさず`gameState.pendingPressConference`で
  保留し、プレイヤーが「もみ消す/全面謝罪/事実無根で強行突破/トカゲの尻尾切り」
  を選ぶまで次の営業日へ進めないようにした(`resolvePressConference`)
- 事務所の清廉度(`gameState.cleanliness`、§11の簡易先取り)を新設。記者会見の
  選択で増減し、悪評・談合の確率にフィードバックする(`cleanlinessRiskMultiplier`)
- 連鎖退職: cleanlinessが閾値を下回った状態で記者会見を経ると、在籍メンバーが
  まれにその場で離脱する

## Phase 8: マクロ環境・エンドコンテンツ（§11）【完了】

- パラダイムシフト(`gameState.era`、`BALANCE.macroEra`): 本来は数年周期の話を
  1週間ループで体感できるよう数日周期に圧縮。`advanceDay`で一定間隔ごとに
  トレンド属性が入れ替わる(`state.js`の`rollNewEra`)
- トレンドの賞味期限: シフト直後は一致ボーナスが最大(`peakMultiplier`)だが、
  同じトレンドが続くほど`staleAfterDays`にかけて`staleMultiplier`まで
  線形に減衰する(`js/battle.js`のresolveTurn、era由来のmult計算)
- アンチ・トレンド(暗黒期): シフト時に`antiTrendChance`の確率で、該当属性が
  むしろ効率減衰の対象になる「暗黒期」になる
- グループ結成の闇(`js/units.js`): 「事務所運営」画面からユニット結成(2〜4人)。
  出演メンバー間のスコア偏重(センター格差)が続くとギスギス度(tension)が蓄積し、
  上限で強制解散(ファン減少)する。共演かつ非解散のユニットは成功報酬の
  ファン増加にボーナスが乗る。判定用に`battle.js`の各performerへ
  `totalScoreGained`の累積を追加した
- 事務所の「裏の顔」蓄積: Phase 7で先取り実装した`cleanliness`指標に
  `reputationLabel`(クリーン事務所/普通の事務所/イロモノ事務所)を追加し、
  「事務所運営」画面に表示するようにした
