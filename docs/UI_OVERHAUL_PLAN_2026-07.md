## ⓪ナビゲーション原則（モーダル/別画面の統一ルール）

「モーダルなのか別画面なのかハチャメチャ」という指摘への対応として、以下のルールを明文化し、全画面をこの基準で再分類する。

- **別画面（専用screen、戻るボタン付き）**: 一覧+詳細、複数ステップの選択・編集、内容が長くスクロールを要するもの。
  → タレント一覧／タレント詳細／レッスン／**タスク（今回モーダルから格上げ）**／オファー一覧／スカウト／**グループ（今回モーダルから格上げ）**／契約更改／バトル
- **モーダル（閉じるボタンのみ、ホーム画面上に重ねて表示）**: 参照+ワンタップ操作のみで完結する単純な内容。
  → 事務所情報／投資・宣伝／設備・採用／融資／ランキング／設定

この結果、④タスク・⑥グループは当初案の「ホーム→タレント展開→モーダル」から「ホーム→タレント展開→別画面」に変更する（`main.js`に`screen = "taskBoard"`/`screen = "unitEditor"`等を追加し、`renderHome`のタレントサブ行からは`open-modal`ではなく画面遷移アクションに切り替える）。

3. **一覧の見た目をタレント一覧と統一**: ②で作るリストデザイン（1行1件、ポートレート等）に合わせる。

## 実装の進め方（提案）

規模が大きいため、依存関係の少ない順に段階分割することを提案する。要確認事項はすべて解決済み（下記「決定事項」参照）のため、フェーズ4を独立させず各フェーズに組み込んだ。

1. **フェーズ1（横断的な見た目統一・小修正）**: ①⑫（ホーム見出し削除/高さ統一/ファン単位/設定ボタン位置）、②の一覧スクロール化（他画面へも展開）、③の円形アイコン・カッコ書き廃止・レイアウト入替、⑨のグラフ化は後回し可。
2. **フェーズ2（一覧系のデザイン統一 + モーダル/別画面の再分類）**: ②タレント一覧のカード再設計（パワプロ式ランク表示含む）→③のランク表示ロジックと共通化、⑤⑥⑪のリスト表示統一（同じコンポーネントを流用）。同時に⓪のルールに沿って④タスク・⑥グループをモーダルから別画面へ切り替える（`main.js`のscreen追加・renderHomeのアクション変更）。⑥のグループ人数上限を4→7に変更。
3. **フェーズ3（データモデル変更を伴うもの）**: ③特殊能力の正負色分け（`TALENTS`にtypeフラグ追加）・歩合支払い履歴記録、④レッスン/タスクの「週送り時実行」化（`advanceDay`シーケンス変更）、⑤週送り時バトルへの手動プレイ誘導化（`gameState.pendingBattles`新設）、⑩シングルリリースのゲート化、⑪売上枚数・永久ランキング。
4. **フェーズ4（設計方針の要相談が残る項目）**: ⑦スカウトの行き先/募集方法の統合方針（現状「不自然」との指摘のみで具体案は未決定のため、実装前に再度方向性をすり合わせる）。

### 決定事項（確認済み）

- ⑥グループの最大人数: **7人に変更**（`FORMATIONS.grand_septet`が既に7人対応済みと確認）。
- ⑤週送り時バトル: **週送り後に該当バトルへ手動プレイ誘導**（自動計算はしない）。
- ③特殊能力の正負区分フラグ: **`masterData.js`のTALENTSに追加してよい**。
- ③歩合支払い履歴の新規記録: **`state.js`に追加してよい**。
- ⓪モーダル/別画面の統一ルールを新設し、④タスク・⑥グループを別画面に格上げ。
